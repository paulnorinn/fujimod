## ภาคผนวก B — Windows: build emulator ได้แล้ว (Unicorn + clang-cl) — VERIFIED

### B.1 สิ่งที่แก้ + verify แล้ว

`crates/emulator-cpu-unicorn/sys/build.rs` (แก้ 3 จุด):

1. `breaks_configure` (บรรทัด 6-9) ปฏิเสธ path ที่มี `:` แต่ทุก absolute path ของ Windows
   มี drive colon → `assert!` ที่บรรทัด 58 panic ทันที (`no space-free directory for the Unicorn build`)
   **แก้:** strip `X:` prefix ก่อนตรวจ — MSYS shell ที่รัน QEMU configure รายงาน path เดียวกันเป็น
   `/c/...` อยู่แล้ว จึงไม่มี colon ที่ configure ปฏิเสธ
2. MSVC `cl.exe` สร้าง QEMU ไม่ได้ (`cputlb.c: error C2065: '__ATOMIC_RELAXED'` — ไม่มี C11 stdatomic ของ GCC/Clang)
   **แก้:** บน Windows บังคับ generator `Ninja` และ panic ด้วยข้อความอ่านรู้เรื่องถ้าไม่ได้เลือก clang-cl
3. `/FIprocess.h` — โค้ด perf-map ที่ fujimod เพิ่มใน
   `vendor/unicorn/qemu/accel/tcg/translate-all.c:65` เรียก `getpid()` โดยไม่ include `<process.h>`
   **แก้:** บังคับ include ผ่าน cflag

**คำสั่ง build (ต้องตั้ง `CC`/`CXX` เป็น clang-cl เต็ม path):**
```powershell
$env:CC  = "$env:LOCALAPPDATA\mise\installs\conda-clang\23.1.4\Library\bin\clang-cl.exe"
$env:CXX = $env:CC
cd E:\github\fujimod
mise exec -- cargo build --release -p fujimod-emulator-cli   # -> Finished `release` profile (exit 0)
```

**ผล:** `fujimod-emulator-cpu-unicorn` (Unicorn 113 targets) และ `fujimod-emulator-cli` (ทุก crate ของ emulator)
**build ผ่านจริงบน Windows** — งานนี้เคยทำได้เฉพาะบน macOS

### H.3 item 3 — eye sensor `i2c0 0x44`: RE ที่ได้ (register protocol ต้องรอกล้อง)

ทำ static RE จาก `FWUP0008.DAT` (แตก segment 5/6 ด้วย `fujimod._native.firmware.scan/decompress`,
แล้ว disassemble ด้วย `cargo run -p fujimod-corpus --example disasm`)

**1. Decode I2C descriptor table `0xd7cbb8` (11 อุปกรณ์, stride 3 = addr, bus, width/select)**
ผู้เข้าถึงคือ `0xb1123c` (=`0xd7cbb8 + index*3`, index ≤ 10) และ bus→cell map ที่ `0xd7cbb4`:

| device | address | bus | width |
|---|---|---|---|
| 0,1 | 0x30 | 0 | 1 |
| 2 | 0x18 | 1 | 1 |
| **3** | **0x44** | **0** | **1** |
| 4 | 0x39 | 1 | 1 |
| 5 | 0x72 | 0 | 1 |
| 6 | 0x19 | 1 | 1 |
| 7 | 0x0c | 1 | 0 |
| 8 | 0x1c | 1 | 1 |
| 9 | 0x0a | 1 | 1 |
| 10 | 0x36 | 1 | 1 |

→ **ยืนยัน RE ของ handover เป๊ะ**: device 3 = bus 0 addr **0x44** (eye sensor), device 10 = bus 1 addr **0x36** (fuel gauge)

**2. Accessor `0xb31d68` (สิ่งที่ handover เรียกว่า eye-sensor accessor) อ่านอะไร**
- `0xb94708` = settings reader → อ่าน setting `0x11b1`, `0x11b3`, `0x11b2` (ตาราง `0xd7fd90`) แล้วคูณเก็บที่ `0xe87598+0x12/+0x14`
- เรียก `0xb1123c` ด้วย device index **3** แล้ว `0xb10eb4` อ่าน **2 ไบต์** เข้า buffer → คืนค่า bool (nonzero)

### H.3b CORRECTION (รอบ 7) — สแกน caller รอบก่อนผิด: `0xb31d68` **มี caller 22 จุด**

> ⚠️ ข้อมูลใน H.3 ที่ว่า “ไม่พบ `bl` caller หรือ data reference ไปที่ `0xb31d68` เลย” **ไม่ถูกต้อง**
> เพราะสคริปต์สแกนใช้ `(w & 0xff000000) === 0xeb000000` ซึ่งใน JavaScript บิต-op แปลงเป็น int32
> ทำให้ค่าที่มีบิตสูง (0xEB…) กลายเป็นค่าลบและไม่เท่ากับค่าคงที่ → นับได้ 0 ทุกครั้ง
> แก้เป็น `(w >>> 24) === 0xeb` แล้วได้ผลจริง: **BL words 43,692 (seg5) / 138,877 (seg6)**

**ผลสแกนใหม่ (seg5, base 0xa51000)**

| ฟังก์ชัน | callers |
|---|---|
| `0xb31d68` (eye-sensor accessor) | **22** (0xb31df4 … 0xb3253c) |
| `0xb1123c` (I2C descriptor lookup) | 16 |
| `0xb10eb4` (transfer 2 ไบต์) | 19 |
| `0xb94708` (settings reader) | 1,346 |

**โปรโตคอล eye sensor ที่ถอดได้ (จาก `0xb31d68` + ตาราง `0xd7fd90`)**

`0xb31d68(n)` ส่ง 2 ไบต์ไปยัง **device index 3 = bus 0 / addr 0x44**
(ไบต์แรก = command, ไบต์ที่สอง = ค่าจาก settings หรือ default ในตาราง) แล้วคืน 1 เมื่อสำเร็จ

| n | command | settings key | default payload |
|---|---|---|---|
| 0 | `0x01` | `0x11a2` | `0x08` |
| 2 | `0x02` | `0x11a4` | `0x40` |
| 7 | `0x03` | `0x11a9` | `0x04` |
| 10 | `0x04` | `0x11ac` | `0x03` |

caller `0xb31de8` ทำ `cfg(0) | cfg(2) | cfg(7) | cfg(10)` = ตรวจว่า “ตั้งค่า eye sensor ครบ 4 ช่อง”

**ยังไม่รู้ (ต้องใช้กล้อง):** ทิศทาง transfer (write ผ่าน `0xb10eb4` หรือ read ผ่าน `0xb110fc`)
และค่าที่อุปกรณ์ตอบจริง — การบูต X-Pro2 บน emulator ปัจจุบันไม่แตะ device นี้เลย (boot ผ่านโดยไม่เกิด refusal)
