## 3. งานที่ต้องทำต่อ (เรียงตามลําดับที่ควรทำ)

### 3.1 [สำคัญสุด] item 3 — model eye sensor `i2c0 0x44`

**สิ่งที่รู้แล้ว (จาก firmware RE — ยืนยันจาก disasm):**

| อย่าง | ค่า |
|---|---|
| ที่อยู่ I2C | bus 0 / **0x44** (device index 3 ใน descriptor table) |
| descriptor table | `0xd7fd90` โครง 12 ไบต์/รายการ: `+0`=command, `+4`=settings key, `+8`=default |
| accessor | `0xb31d68(n)` — function นี้ถูกเรียก 22 ครั้ง |
| helper A | `0xb10eb4` — เรียกด้วย `(device, 2, &bytes)` ใน seg5 ⇒ **รูปร่างเหมือน write 2 ไบต์** |
| helper B | `0xb110fc` — เรียกด้วย `(device, 1, &cmd, count, &out)` ใน seg6 ⇒ **รูปร่างเหมือน read** |
| "ครบ 4 ช่อง" | `0xb31de8` = `cfg(0)|cfg(2)|cfg(7)|cfg(10)` |

| n | command | settings key | default payload |
|---|---|---|---|
| 0 | `0x01` | `0x11a2` | `0x08` |
| 2 | `0x02` | `0x11a4` | `0x40` |
| 7 | `0x03` | `0x11a9` | `0x04` |
| 10 | `0x04` | `0x11ac` | `0x03` |

> หมายเหตุ: “write/read” เป็นการตีความจากอาร์กิวเมนต์ที่ส่งเข้า helper ไม่ใช่จาก datasheet ของอุปกรณ์

**ที่ยังไม่รู้ (ต้องใช้กล้อง) — 2 ข้อเท่านั้น:**
1. **ทิศทาง**: firmware *เขียน* 2 ไบต์นี้ไปที่ 0x44 (ผ่าน `0xb10eb4`) หรือ *อ่าน* (ผ่าน `0xb110fc`)?
2. **ค่าที่อุปกรณ์ตอบกลับ** เมื่ออ่าน (ถ้าเป็นการอ่าน)

**วิธีเก็บข้อมูล (read-only ทั้งหมด):**
- ทางที่ปลอดภัยสุด: ใช้ emulator ที่บูตได้อยู่แล้ว (`run_xpro2_emu_win.py`) แล้วเปิด trace ที่ I2C controller (`emulator-xpp`/`xp4-io` i2c) ดูว่า firmware ยิง transaction อะไรไป 0x44 บ้าง → ได้ทั้งทิศทางและลำดับ
- ถ้าจะดูของจริง: ใช้ USB proxy / diagnostic memory read ของรีโป อ่าน register ของ I2C controller ขณะอยู่หน้าเมนูที่เกี่ยวกับ eye sensor — **ห้ามเขียน**
- ที่อ่านมาแล้ว: `0xe87592=0`, `0xe87594=0`, `0xe875d4=0` (ตอน idle ทั้งหมดเป็น 0)

**เมื่อได้ข้อมูลแล้ว:** เพิ่ม device ใน discovery ของ `xpro2` (ที่เดียวกับที่ประกาศ `i2c0`), ให้ตอบ command ตามตาราง + ใส่ค่า default จาก settings key
แล้วเพิ่ม test เทียบกับค่าที่ดักได้จาก trace (ไม่ใช่ค่าที่เดา)

**ข้อควรระวัง:** อย่าใส่ค่า "เดา" ลงใน catalog — `.generated` และ test ในรีโปจะเทียบกับ generator
ถ้ายังไม่รู้ค่าจริง ให้ประกาศเฉพาะ "device มีอยู่ + command ที่รู้" แล้วปล่อย payload มาจาก settings/default ตามตาราง ซึ่งตรงกับที่ firmware ทำอยู่แล้ว

### 3.2 item 9 — `settings/first-start.generated.json`

**สถานะ:** ไม่มี generator ในรีโป (ตรวจ 5 ทางแล้ว: ไม่มีไฟล์, ไม่มี locator ใน `crates/corpus/src/locators/`,
`catalog-settings` มีแต่ schema, `generation.generated.json` ระบุ unavailable, AGENTS.md ห้ามแก้ `.generated` มือ)

**ต้องเก็บอะไรจากกล้อง (อ่านอย่างเดียว):**
- settings store ของ X-Pro2 ตาม §3.5 ใน handover zip (`xpro2-511-handover/`)
- ค่าที่ต้องการคือ **ชุด key→value ตั้งต้น** สำหรับ `settings.generated.json` และสถานะ first-start

**เมื่อได้ข้อมูล:**
1. ถ้าในอนาคตรีโปมี generator → ใส่ input แล้วรัน generator (อย่าเขียนไฟล์เอง)
2. ถ้ายังไม่มี → ต้องตัดสินใจร่วมกับเจ้าของรีโปว่าจะเพิ่ม generator/locator หรือยอมให้ไฟล์นี้มาจาก pipeline ภายนอก
   (ผมยังไม่ทําต่อเพราะไม่รู้ว่า pipeline ภายนอกหน้าตาเป็นอย่างไร — อย่าเดา)

### 3.3 live view จริง (ต่อเนื่องจากข้อ 2/4)

ตอนนี้ `Session::set_picture` + `RunScene::Xpp` ทำงานแล้ว แต่ยังไม่มี "ภาพจริง" จากเซนเซอร์

## ภาคผนวก A — แผนใช้งานกับกล้อง (เรียงตามความเสี่ยงน้อย → มาก)

> ทุกขั้นเป็น **read-only** จนกว่าจะระบุว่าเขียน

### A.1 ก่อนแตะกล้อง (ไม่ใช้กล้อง 30 นาที)
1. `python _handover/run_xpro2_emu_win.py 1500` → ต้องเห็น `display0 words count: 113`
2. เปิด trace ของ I2C ใน emulator แล้วดูว่า firmware ยิงอะไรไปที่ **0x44** บ้าง
   - ถ้าเห็น transaction = ได้ "ทิศทาง + ลําดับ" ฟรี โดยไม่ต้องแตะกล้อง
   - ถ้าไม่เห็นเลย (เหมือนตอนนี้ ที่ boot ไม่แตะ device นี้) → ไป A.2

### A.2 เก็บจากกล้อง (read-only)
| ลําดับ | เก็บอะไร | เอาไปทําอะไร |
|---|---|---|
| 1 | firmware version / build (ยืนยันว่าเป็น 5.11) | ยืนยันว่าใช้ `xpro2-511` ถูกตัว |
| 2 | settings store ตาม §3.5 ของ handover zip | ใช้ทํา `settings.generated.json` + `first-start.generated.json` (item 9) |
| 3 | ค่า `0xe87592`, `0xe87594`, `0xe875d4` ตอน **เอามือบัง eye sensor** และตอน **ไม่มีอะไรบัง** | ค่า 3 ตัวนี้เปลี่ยนตามสถานะหรือไม่ — ถ้าเปลี่ยน = เป็น flag ที่ใช้ได้ |
| 4 | register ของ I2C controller ขณะอยู่หน้าเมนูที่เกี่ยวกับ eye sensor | ยืนยัน 0x44 + ทิศทาง |
| 5 | ค่าที่ 0x11a2 / 0x11a4 / 0x11a9 / 0x11ac ใน settings store | เทียบกับ default ที่ firmware ฝังไว้ (0x08 / 0x40 / 0x04 / 0x03) |

> ถ้าค่าในข้อ 5 **ต่าง** จาก default → นั่นคือค่าที่ผู้ใช้ตั้งไว้ ต้องใช้ค่านี้ใน model ไม่ใช่ default

## ภาคผนวก B — ขับเมนู X-Pro2 ใน emulator (อัปเดต 2026-11-27)

**กุญแจ:** หลังบูตต้อง `board.set_idle_stop(False)` ไม่งั้น guest จะหยุดที่ idle loop
และ contact จะค้างในคิว (นี่คือสาเหตุที่ probe ก่อน ๆ ดูเหมือนปุ่มไม่ทำงาน)

```python
board = n.emulator.Board(...)
board.mem_write(0, 0, FFBOOT)
board.set_idle_stop(True)
for _ in range(1500):
    board.run_for_instructions(25_000_000, 500_000)
ref = json.loads(n.catalog.resolve_configuration("xpro2-511"))["reference"]
board.connect_controls(json.dumps(ref), 48_000_000)
board.set_idle_stop(False)                      # <-- สําคัญ
board.run_for_instructions(20_000_000, 500_000)  # quantum ต้องตรงกับ board
```

**ตรวจว่า UI ตอบสนอง:** hash ของ `device_states("xpp-display-output")[0]["words"]`
**อ่าน I2C trace:** `device_states("designware-i2c")[i]["bus"]["transfers"]`
(address, read, bytes) — ring เก็บ 64 รายการล่าสุด

**สิ่งที่พบแล้ว** (ดู `STATUS-xpro2-2026-11-21.md` H.12):
- firmware แตะ bus 1: `0x1c` (accel), `0x36`, `0x39` (eye sensor) — ไม่แตะ bus 0 (`0x44`)
- eye sensor `0x39` ถูก poll ด้วย `0xa0|reg` + อ่าน status → model ตอบค่าที่ประกาศ

**ถ้าจะไปต่อกับ item 3:** หา path เมนูไป SCREEN SET-UP → EYE SENSOR
แล้วดูว่า `0xe87592/94/d4` หรือ I2C trace เปลี่ยนหรือไม่ (ใช้ hash ของ display เป็นตัวบอกหน้า)
